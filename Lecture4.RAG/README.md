## Задание 1. Три датасета

Собрать датасеты под оценку RAG: happy path не меньше 50 вопросов, негативный не меньше 20, метаморфный не меньше 3 групп отношений.

Вопросы написаны по 17 документам требований, а не сгенерированы моделью: нужны проверяемые ожидаемые ответы, иначе нечем мерить. Каждый вопрос помечен типом, чтобы потом считать метрики по срезам.

| Датасет | Размер | Состав |
|---|---|---|
| happy path | 50 | 35 фактических, 11 объясняющих, 3 многошаговых, 1 сравнительный |
| негативный | 20 | 14 вне документации, 6 с ложной посылкой |
| метаморфный | 15 | 3 группы по 5 формулировок, 6 типов трансформаций |

Негативный датасет намеренно разделён на два вида. Вопрос вне документации требует отказа. Вопрос с ложной посылкой («пароль минимум 6 символов — верно?») требует обратного: система должна поправить, а не отказаться. Если смешать их в одну пачку, метрика отказа покажет среднее между двумя разными ожиданиями и будет бессмысленной — на прогоне это подтвердилось, 0.714 против 0.167.

Метаморфные группы — один и тот же факт пятью способами: нейтрально, вежливо, с лишним контекстом, как проверка утверждения, обрывком без вопросительного слова. Ответ должен совпадать по сути во всех пяти.

Выводы:

- 85 вопросов на 17 документов — это 5 вопросов на документ, мало для покрытия, но достаточно, чтобы увидеть систематические провалы;
- скрипт генерации сам проверяет датасеты на дубли и пустые поля перед записью: формулировки в метаморфных группах близкие, и проверять их глазами ненадёжно;
- ожидаемый ответ для отказных вопросов должен быть одинаковой строкой, иначе метрики сравнивают систему с пятнадцатью разными формулировками отказа.

## Задание 2. Оценка системы двумя фреймворками

Посчитать Answer Relevancy, Context Relevancy и Faithfulness на happy path минимум двумя фреймворками, Answer Precision и Restricted Refusal — на негативном и метаморфном. Отчёт с результатами, найденными ошибками и выводами.

Сбор ответов и подсчёт метрик разведены по разным скриптам: 85 вопросов отправлены в систему один раз и сохранены в файл вместе с контекстами, метрики считаются из файла. Падение на середине прогона не теряет ответы.

Судья у обоих фреймворков один — `gpt-4.1-mini`, порог 0.7, иначе сравнение нечестное.

| Метрика | EvaliQA | DeepEval | ниже 0.7 |
|---|---|---|---|
| Answer Relevancy | 0.934 | 0.961 | 5 / 4 |
| Faithfulness | 0.528 | 0.972 | 28 / 1 |
| Faithfulness после починки | 0.926 | 0.972 | 5 / 1 |
| Context Relevancy | 0.483 | 0.364 | 39 / 47 |

| Датасет | Метрика | Результат |
|---|---|---|
| негативный | Answer Precision | 0.428 |
| негативный | Restricted Refusal | 0.550 |
| метаморфный | Answer Precision | 0.352 |

Context Relevancy по типам вопросов: фактические 0.435, объясняющие 0.532, многошаговые 0.793, сравнительные 0.660.

Выводы:

- поиск — слабое место, генерация — сильное. Ответы хорошие (0.93 и 0.96), обоснованность хорошая (0.93 и 0.97), а релевантность контекста 0.48 и 0.36. Модель вытягивает ответ из плохой выборки;
- система всегда возвращает ровно пять фрагментов независимо от вопроса. На узком фактическом вопросе четыре из пяти не по делу — отсюда 0.435 против 0.793 на многошаговых, где пять фрагментов действительно нужны. Первое, что стоит попробовать, — переменное число фрагментов;
- баг в `eval-ai-library` 0.8.4: Faithfulness ставит 0.00 русским ответам. Проверка цитаты разбивает текст регуляркой `[a-z0-9]{3,}` — только латиница, на русской цитате набор слов пустой, и правильный вердикт судьи заменяется на «нет подтверждения». Цитата при этом есть в контексте дословно, питоновский `in` это подтверждает. Добавила кириллицу — среднее поднялось с 0.528 до 0.926 и совпало с DeepEval;
- два фреймворка на одних данных расходятся на 0.026 по Answer Relevancy и 0.119 по Context Relevancy. Расхождение 0.444 по Faithfulness было не разницей подходов, а багом. Один фреймворк его бы не показал;
- модель-судья решает, работает ли метрика вообще. На `gpt-4o-mini` Faithfulness в DeepEval не считается: судья генерирует 16 384 токена на промпт в 990 и упирается в лимит вывода. На `gpt-4.1-mini` — семь секунд на кейс;
- одна фактическая ошибка системы: на вопрос «склад с продуктами удаляется автоматически вместе с товарами, верно?» ответила «да, верно», хотя документация это запрещает. Остальные пять ложных посылок система поправила;
- Answer Precision сравнивает тексты буквально и штрафует за многословность, его 0.352 нельзя читать как качество. Разброс внутри метаморфных групп при этом крошечный (0.150–0.170), то есть к переформулировкам система устойчива;
- 50 вопросов — грубая сетка, один кейс весит 0.02. Числа показывают, куда смотреть, но не измеряют систему в абсолютных значениях;
- весь прогон 85 вопросов на двух фреймворках обошёлся в 19 центов.
