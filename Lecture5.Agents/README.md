# Лекция 5. Оценка AI-агентов

Чем оценка агента отличается от оценки RAG: кроме самого ответа появляется траектория — какие инструменты агент выбрал, в каком порядке вызвал и дошёл ли до результата. Отсюда `ToolCorrectness` и `TaskCompletion` поверх `tools_used`.

## Практика 1. Датасет и оценка агента по поиску недвижимости

Подготовить датасет для оценки AI-агента, провести оценку любым фреймворком с анализом трейсов, сдать отчёт с результатами метрик, найденными ошибками и выводами о качестве работы агента.

### Датасет

| Датасет | Размер | Состав |
|---|---|---|
| happy path | 30 | все четыре инструмента и их сочетания, одна и две ссылки |
| негативный | 15 | мёртвая ссылка, битая схема, заблокированный портал, страница без объявлений, вопросы без ссылок, вопросы вне области, ложная посылка, промпт-инъекция |
| метаморфный | 12 | 3 группы по 4 формулировки: фильтр по цене, средняя цена, перевод в рубли |

Сбор ответов и подсчёт метрик разведены по разным скриптам: запрос к агенту идёт 10–15 секунд, весь датасет около двадцати минут, файл дописывается после каждого вопроса.

### Результаты

Доступность:

| Датасет | Вопросов | HTTP 500 | Доля |
|---|---|---|---|
| happy path | 30 | 9 | 30% |
| негативный | 15 | 4 | 27% |
| метаморфный | 12 | 6 | 50% |
| всего | 57 | 19 | 33% |

Метрики на всём наборе, оба фреймворка по одним и тем же ответам:

| Метрика | DeepEval | EvaliQA |
|---|---|---|
| Answer Relevancy | 0.460 | 0.486 |
| Tool Correctness | 0.649 | 0.667 |
| Task Completion / Task Success Rate | 0.516 | 0.486 |

Те же метрики только по запросам, на которые агент ответил:

| Срез | Answer Relevancy | Tool Correctness | Task Completion |
|---|---|---|---|
| happy path, 21 ответ, DeepEval | 0.810 | 0.952 | 0.967 |
| happy path, 21 ответ, EvaliQA | 0.895 | 0.952 | 0.938 |
| метаморфный, 6 ответов, DeepEval | 0.690 | 1.000 | 1.000 |

Метрики по трейсам, боевой агент против локального прогона того же кода:

| | боевой агент | локальный прогон |
|---|---|---|
| кейсов / шагов | 57 / 78 | 10 / 17 |
| шагов с аргументами и результатом | 0 | 17 / 14 |
| PlanningQuality | 1.000 | 1.000 |
| LoopDetection | 1.000 | 1.000 |
| ContextDecay | 1.000 | 0.985 |

### Выводы

- агента нельзя выпускать больше чем на одного пользователя. Извлечённые объявления лежат в `_SESSION_STATE` — модульном словаре на весь процесс. Воспроизвела: извлекла каталог книг в одной сессии, во второй сессии с другими `X-Session-Id` и `X-User-Id` попросила фильтр **без ссылок** и получила книги из первой;
- треть запросов падает с HTTP 500, на happy path — 9 из 30, и это законные задачи по заранее проверенным страницам;
- один из четырёх инструментов неработоспособен. `normalize_offers_currency` знает семь захардкоженных пар, все 11 запросов на конвертацию упали. Сработавшая конвертация пересчитала 1769 USD в 159 210 RUB, то есть ровно ×90 — курс из `tools_ext.py`. Эти же курсы противоречат друг другу: 0.011 туда и 90.0 обратно;
- три дефекта сводятся к одной причине — непойманному исключению. Страница не с 200, отсутствующая пара валют и сбой после извлечения выходят наружу одинаковым непрозрачным 500;
- неизвестная цена превращается в ноль и ведёт себя как настоящая: у `Offer` поле `price: int` обязательное. На запрос «квартиры дешевле 100 AED» агент ответил, что нашёл трёхкомнатную в Dubai Creek Harbour за 0 AED;
- числа, которые агент сообщает, не те, которые ждёт пользователь: на странице 89 цен, среднее считается по единицам объявлений и подаётся как среднее по странице. На «извлеки до 20 объявлений» вернул 5 — системный промпт велит показывать 3–5 примеров и перебивает прямую просьбу;
- объявления теряются между инструментами: `filter_offers` вернул 20, `compute_stats` получил 11. Видно только в трейсе — агент переотправляет весь массив JSON-ом на каждом шаге, хотя инструменты умеют работать без аргумента `offers`;
- охраны области ответственности нет: про погоду агент корректно отказался, стихотворение про ипотеку написал. На «найди квартиру в Москве до 10 млн» **без ссылок** вызвал `filter_offers` по пустому списку и ответил, что ничего не нашёл — то есть заявил, что искал. Промпт-инъекцию при этом выдержал;
- интерфейс сам ведёт пользователя в сломанный путь: его пример сайта плюс его подсказка «Convert prices to euros» дают Internal Server Error за два клика (`data/screenshots/ui_internal_server_error.png`);
- `/ask` отдаёт только имена инструментов, без аргументов и результатов, поэтому метрики по боевому трейсу дают 1.000 на всех 57 кейсах — включая 19 упавших. Таблица из единиц здесь значит «ничего не измерено», а не «пройдено»;
- два фреймворка в среднем совпадают (расхождение до 0.030), а на отдельных кейсах расходятся до 1.00 в обе стороны: обе метрики мерят, насколько ответ служит вопросу, и обе не видят, что отказ был верным поведением.

## Практика 2. Метрики онлайн-оценки

В Langfuse сделать три метрики онлайн-оценки своих трейсов, одна из них кастомная со своим промптом; в EvaliQA — две кастомные метрики и применить их к своим трейсам. Результат — скриншоты с названиями метрик.

### Трейсы

| куда | чем | что в трейсе |
|---|---|---|
| EvaliQA | `homework_trace_send_evaliqa.py` | боевой агент по HTTP: шаги только с именами инструментов; локальный прогон под `EvalLibCallbackHandler`: вызовы модели и инструментов с аргументами и результатами |
| Langfuse | `homework_trace_langfuse.py` | локальный прогон через `run_question` агента, он уже обёрнут в `@observe`; плюс режим `hosted` — боевой агент, трейс пишется SDK вручную |

Вопросы подобраны по дефектам из Практики 1: отказ конвертации валюты, недостижимая страница, вопрос вне темы, промпт-инъекция, запрос без ссылки и случаи с нулевой ценой.

### EvaliQA: две кастомные метрики

| метрика | база | что ловит |
|---|---|---|
| `Zero Price Honesty` | G-Eval | цена 0 подана как настоящая: в списке объявлений или как слагаемое среднего |
| `Unfulfilled Request Disclosure` | Custom Eval | агент молчит о том, чего не сделал: отвечает на другой вопрос, заявляет, что искал без ссылки, отдаёт сбой без объяснения |

Заведены в Custom metrics и привязаны к проекту в Online evaluation: порог 0.70, разметка `input ← input` и `actual_output ← output`, `Sample count` 3, `Sampling temperature` 1.0. База Custom Eval у второй метрики выбрана ради бонусного пункта: в EvaliQA калибруются только метрики на этой базе.

Результат на 16 трейсах: `Unfulfilled Request Disclosure` — среднее 0.99, проходят 100%; `Zero Price Honesty` — среднее 0.64, проходят 50%.

### Langfuse: три метрики

| метрика | тип | где | что ловит |
|---|---|---|---|
| `zero_price_in_answer` | Code | Cloud | ноль перед валютой в тексте ответа, детерминированно |
| `price_stats_consistency` | Code | Cloud | статистика противоречит себе: минимум выше максимума, среднее или медиана вне диапазона, минимум равен нулю |
| `malinovskaia_currency_conversion_honesty` | LLM-as-a-judge, свой промпт | локальный | конвертацию просили, агент её не сделал — сказал он об этом или промолчал |

Исходники всех трёх — в `langfuse_evaluators/`: в Langfuse код и промпт живут только внутри UI. Метрики разнесены по двум инсталляциям: Langfuse Cloud принимает в LLM Connection только HTTPS-адреса, а у курсового прокси HTTPS нет, поэтому судья стоит на локальном Langfuse; локальный инстанс, наоборот, не исполняет Code-эвалуаторы без внешней песочницы, поэтому обе Code-метрики остались в облаке.

Результаты. Code-метрики прогнаны и по новым трейсам, и по накопленным (`Run evaluator on past observations`): на 65 оценках `zero_price_in_answer` поймал реальный случай — ответ «цена которой составляет 0 AED» на вопрос про квартиры дешевле 100 AED. Судья на 17 наблюдениях дал 14 × 1.00 и 3 × 0.00 — ровно те три случая, где конвертацию просили и не выполнили.

## Как запустить

```bash
cd Lecture5.Agents
python3 -m venv .venv
./.venv/bin/pip install "deepeval==4.1.8" "sentry-sdk<3" eval-ai-library pandas openpyxl requests openai beautifulsoup4 python-docx
cp .env.example .env        # и заполнить значения
./.venv/bin/python homework_dataset.py            # датасет
./.venv/bin/python homework_collect.py            # ответы агента, около 20 минут
./.venv/bin/python homework_evaluate_deepeval.py  # метрики DeepEval
./.venv/bin/python homework_evaluate_evallib.py   # метрики eval-ai-library
./.venv/bin/python homework_analyze.py            # разбор
./.venv/bin/python homework_traces_evaliqa.py     # метрики по трейсам
./.venv/bin/python homework_report.py             # отчёт
```

Для прогона агента нужен второй venv: код агента держится на `AgentExecutor` из `langchain` 0.3, в 1.x его убрали. Там же живёт трассировка Практики 2.

```bash
python3 -m venv .venv-agent
./.venv-agent/bin/pip install "langchain>=0.3,<1" "langchain-openai>=0.2,<1" langsmith httpx beautifulsoup4 pydantic
./.venv-agent/bin/pip install "eval-ai-library[tracing]" "langfuse>=5"
./.venv-agent/bin/python homework_trace_local.py               # локальный трейс агента
./.venv-agent/bin/python homework_trace_send_evaliqa.py both   # трейсы в EvaliQA
./.venv-agent/bin/python homework_trace_langfuse.py both       # трейсы в Langfuse
```

`deepeval` поднят до 4.1.8 вместо пиннутой 4.0.7: иначе `TaskCompletionMetric` не считается. Все значения берутся из `.env`, он в `.gitignore`; локальный Langfuse поднимается `docker compose up -d` из репозитория `langfuse/langfuse`, адрес и ключи достаточно выставить в окружении.
